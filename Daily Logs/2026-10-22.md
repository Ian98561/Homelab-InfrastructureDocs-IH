# 2026-10-22 — Off-Site Gateway Hardware and Debian Installation

> Public-facing version: exact host identifiers, administrator usernames, and off-site location are generalized.

## Notes

- Began repurposing a **Lenovo ThinkCentre M70q Gen 3** as an **off-site gateway**, a future remote entry point for the homelab.
- The mini PC had been decommissioned after an earlier malware/ransomware compromise. Chose a clean Debian 13 installation instead of trusting the previous operating system.
- Selected a minimal **Debian 13 (Trixie), CLI-only** system, with SSH server and standard system utilities and no desktop environment.
- Used the **512 GB WD PC SN740 NVMe** for the new OS, with a simple ext4 layout, no disk encryption, and GRUB installed to the NVMe. Left the additional 1 TB HDD untouched pending health inspection.
- Set a dedicated hostname for the gateway, left the installer domain blank, and created a non-root administrator account.
- Worked through installer networking decisions and opted to configure networking during installation. Final Ethernet/DNS/SSH verification continued after midnight on October 23.

## Extra Additions

- Defined the intended role: private remote administration over Tailscale first, with **a separate future WireGuard tunnel** for game traffic from the CGNAT home network.
- Planned eventual placement at a separate trusted off-site network, where a public-IP path might make externally accessible game services possible, subject to router and ISP verification.
- Explicitly avoided repurposing the old 1 TB HDD for backups until diagnostics were completed.

## Problems/Solutions Ran Into

- **Untrusted old OS:** Addressed by choosing a clean install onto the NVMe. No data-preservation requirement for the previous OS was identified.
- **Install/network decisions:** Settled on a command-line-only gateway, initially minimizing installer complexity; network troubleshooting continued the following day.
